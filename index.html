Show HN: Type-C – variants, options, generics and pattern matching for C

2026-11-22 @ 18:40:57Points: 5Comments: 0

Of course there is Swift, Ocaml or Rust for situations like that, but then you are either forced to convert the entire codebase, or add a runtime library or go through the pain of bridging C to the new language. Sometimes there are no compilers for the target architecture too when you are working on embedded stuff.

This is where Type-C comes in. It works as a preprocessor like TypeScript and calls the original C driver behind the scenes. Your code stays normal C for the most part, so you can predict how the code will be laid out. TypeC is a full superset of C11, so any C11 code compiles as is.

Want to use TypeC just for one file? Rename to .tc and use the features you want, the rest of the codebase stays the same. This works for kernel or baremetal code too as there is no runtime or extra libararies.

There are examples of TypeC code as well as real-world tests of converting existing code to TypeC on the GitHub page.

This is how the code looks like for an expression evaluator: type expr = | Num(int value) | Add(const expr l, const expr r) | Mul(const expr l, const expr r) | Div(const expr l, const expr r); 

  static result(int, eval_error)
  eval(const expr *e)
  {
      int d;

      match (*e) {
      case Num(value):
          return (Ok(value));
      case Add(l, r):
          return (fit((long long)try eval(l) + try eval(r)));
      case Mul(l, r):
          return (fit((long long)try eval(l) * try eval(r)));
      case Div(l, r):
          d = try eval(r);
          if (d == 0)
              return (Err(DivByZero));
          return (fit((long long)try eval(l) / d));
      }
  }

  % typec -std=c11 -Wall -Wextra eval.tc
